# SPEC 001: 주문 확정 시 재고 배정

## 상태와 관련 요구사항

- 기록일: 2026-09-29
- 관련 요구사항: 7, 18, 26
- 상태: 사용자 결정 및 기록 승인 완료. 구현·동작 검증 전.

## 원래 요구사항과 충돌

요구사항 7은 장바구니에 담는 것만으로 재고를 줄이지 않도록 하지만, 요구사항 26은 담는 즉시 판매 재고를 차감하도록 한다. 같은 동작에 서로 다른 재고 처리 기준이 있어 함께 적용할 수 없다.

## 사용자 결정과 이유

사용자 발언: “장바구니에 담을 때 재고를 차감하지 말고 먼저 결제를 한 사람이 재고를 가져가는 걸로 하자.”

- 요구사항 7을 유지한다. 장바구니에 담아도 재고를 차감하거나 확보하지 않는다.
- 요구사항 26의 즉시 차감 정책을 수정한다. 모의 주문 확정 시 현재 재고를 다시 확인하고, 성공적으로 확정할 때 주문 수량을 차감한다.
- 재고는 모의 주문 확정에 먼저 성공한 고객에게 배정한다.
- 선택 이유: 장바구니에 먼저 담은 순서가 아니라 결제를 먼저 완료한 고객에게 재고가 돌아가도록 한다.
- 실제 결제 연동 없이 모의 주문 확정으로 처리한다는 기존 범위를 유지한다.

AI가 위 기록 내용을 제안했고 사용자가 “응 기록해줘”라고 승인했다.

## 별도 결정이 필요한 사항

- 장바구니에 현재 재고보다 많은 수량을 담을 수 있는지.
- 주문 확정 시 일부 상품의 재고가 부족할 때 주문 전체를 거절할지 등 구체적인 실패 처리.

위 사항은 이번 결정에 포함되지 않았으며 관련 구현 전에 사용자와 논의한다.

### 후속 결정 (2026-09-29)

위 문단은 최초 기록 당시의 미정 사항을 보존한 것이다. 이후 사용자가 일괄 승인안 4~6번을 승인했다. 현재 재고를 넘는 담기·수량 증가는 거절하며, 주문 확정 시 재고·쿠폰에 문제가 있으면 전체 주문을 거절하고 기존 재고·쿠폰·장바구니를 유지한다. 중복 주문과 재고 초과 판매도 방지한다. 상세 기준과 이유는 [SPEC 002](002-purchase-policies.md)에 기록했다. 구현·검증은 아직 수행하지 않았다.

## 실제 구현·확인 결과

- 문서 반영: PRD와 요구사항 충돌 기록에 결정 및 이유를 반영했다.
- 앱 구현: 미착수.
- AI 동작 검사: 미실행.
- 사람의 화면 조작 확인: 미실행.

## 후속 구현·확인 기록 (2026-09-29, 사후 정리)

위 ‘미착수·미실행’은 최초 작성 시점의 상태다. 이후 `server/core.ts`에서 장바구니 담기·수량 변경은 재고를 차감하지 않고, `order.place`가 선택 상품의 현재 재고를 `quote()`로 다시 검사한 뒤 주문 확정 시에만 차감하도록 구현했다. 서버는 작업 결과를 복제 상태에 적용하고 SQLite 트랜잭션으로 저장하므로 실패한 작업은 저장 상태에 반영되지 않는다. `tests/shop.test.ts`에는 두 고객이 같은 마지막 재고를 장바구니에 담은 뒤 먼저 확정한 고객만 주문하는 사례가 있다. 기존 브라우저 확인 범위는 [SPEC 006](006-address-default-fix.md), 상품·고객별 확인 범위는 [상품 탐색 검토](007-product-discovery-review.md)에 기록돼 있다. 이 후속 기록은 기존 코드와 검사 기록을 정리한 것이며, 이번 문서 보완에서 새 동작 검사를 실행하지 않았다. 사람의 직접 화면 확인 결과는 아직 전달받지 않았다.
