# SPEC 005: 구매자 웹앱 구현

- 시작: 2026-09-29. 사용자 요청 “그럼 이제 구현하자”.
- 기준: PROBLEM.md, PRD.md, SPEC 001~004의 사용자 승인 정책. 기존 자료를 보존한다.
- 범위: 초기 데이터로 상품 탐색, 고객별 찜·장바구니·배송지, 쿠폰 적용, 주문·취소·다시 담기, 추가 기능 4개, 지속 저장, 별도 대량 데이터 생성과 검증, API 문서와 제출 자료를 구현한다.
- 검증: 실제 API와 화면 흐름을 실행해 입력 전 기대값과 결과를 비교한다. 사람의 직접 화면 확인은 사용자에게 별도로 안내하며 AI 검증과 구분한다.
- 현재 상태: 작성 시점에는 구현·검증 전. 진행 중 확인 결과를 갱신한다.

## 후속 구현·확인 기록 (2026-09-29, 사후 보완)

위의 "구현·검증 전"은 이 SPEC을 처음 작성했을 때의 상태로 보존한다. 구현 중 이 파일을 갱신하지 못했으며, 다음 내용은 이후 코드와 검사 기록을 대조해 추가했다.

- 구현 위치: `src/main.tsx`의 구매자 화면, `server/core.ts`의 상품·장바구니·주문·취소 처리, `server/server.ts`의 API와 SQLite 저장, `scripts/generate.ts`의 별도 대량 데이터 생성. API 사용법은 `docs/API.md`에 있다.
- 초기 자료: 제공된 `initial-data.json`의 상품 옵션 30개와 고객 4명을 사용한다. 별도 테스트 자료의 상품 옵션 200개·고객 100명·주문 800건 생성 및 재고·취소 금액 검사는 [SPEC 008](008-generated-orders-confirmation.md)에 기록했다.
- AI 확인 근거: 기본 배송지 선택 오류와 후속 화면 검사는 [SPEC 006](006-address-default-fix.md), 상품 탐색 1~6은 [상품 탐색 검증 기록](007-product-discovery-review.md), 주문 확인·변경 19~24는 [주문 검증 기록](007-order-review.md)에 각각 기록했다. 각 문서의 확인 범위와 미확인 항목을 따른다.
- 이번 갱신 시점의 추가 실행: 최신 `main` 기준 `npm test` 12건 통과, `npm run build` 성공. 이는 자동 검사와 빌드 결과이며 전체 요구사항의 사람 확인을 뜻하지 않는다.
- 주문 확인 내용과 실제 확정 주문을 일치시키는 후속 수정은 [SPEC 009](009-order-confirmation-retrospective.md)에 사후 기록했다.
- 사람의 직접 화면 조작과 전체 요구사항별 최종 완료 판정은 아직 이 SPEC에서 확인되지 않았다. 수행하지 않은 결과는 완료로 기록하지 않는다.
