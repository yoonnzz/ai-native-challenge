# SPEC

구현, 기능 추가, 정책 변경, 오류 수정에 착수할 때마다 새 SPEC을 작성하세요. 형식과 작업 단위는 자유입니다.

정한 기준과 이유, 실제 구현과 확인 결과를 작업 중 기록하고 관련 요구사항과 근거를 연결하세요. 아직 결정하거나 실행하지 않은 내용은 구분하고, 이전 판단과 실패 기록은 보존하세요. 제출할 때 전체 SPEC을 포함합니다.

## 기존 작업의 기록 보완 (2026-09-29)

초기 SPEC 001~005의 ‘구현 전·미실행’ 문구는 작성 당시 상태로 보존하고, 각 파일 끝에 이후 구현·확인 결과를 사후 기록했다. 주문 확인 일치 수정 `0056d05`는 착수 시 새 SPEC을 작성하지 못했으므로 [SPEC 009](009-order-confirmation-retrospective.md)에 사후 기록으로 명시했다. 생성기 후속 수정은 [SPEC 008](008-generated-orders-confirmation.md)에 기존 기록이 있다. `007-product-discovery-review.md`와 `007-order-review.md`는 기존에 번호가 중복됐으며, 기록 보존을 위해 파일명과 제목을 바꾸지 않았다. 향후 새 작업은 착수할 때 새 SPEC을 작성하고 실제 구현·확인 결과를 그 문서에 갱신한다.
