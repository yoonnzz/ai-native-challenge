# SPEC 007: 주문 확인·변경 기능 검증

## 범위와 판단

- 2026-09-29 사용자 요청: 요구사항 19~24가 잘 구현되었는지 확인한다.
- 기존 요구사항이나 처리 정책은 변경하지 않는다. 이번 작업은 구현 수정 없이 동작을 검증한다.
- 사용자는 검증 결과를 기록하고 Pull Request를 준비하는 데 동의했다.

## AI가 실행한 확인

- `npm test`: 9건 통과. `npm run build`: 성공.
- 제공된 `initial-data.json`을 사용한 별도 임시 SQLite DB에서 로컬 서버를 실행했다. 기존 저장 자료는 변경하지 않았다.
- 고객 1의 주문 2건을 만들고 주문 번호 2, 1 순서로 표시되는지 확인했다. 주문 목록에는 시각, 대표 상품, 최종 금액, 상태, 상세 버튼이 표시됐다.
- 주문 상세에서 상품·옵션·최초 수량·취소 수량·남은 수량·단가·줄 금액, 배송 정보, 할인·배송비·최종 금액·취소 금액을 확인했다.
- 상품명 검색과 `전체 취소` 필터를 함께 적용해 해당 주문만 표시되는 것을 브라우저에서 확인했다. API의 같은 조건을 적용한 CSV 결과도 대조했다.
- 주문의 상품 1개를 일부 취소한 뒤 상태가 `일부 취소`로 바뀌고 해당 재고가 1개 복구되는 것을 확인했다. 남은 상품을 전체 취소한 뒤 주문 기록이 유지되고 취소 금액이 최종 금액과 같아지는 것을 확인했다.
- 브라우저에서 수량 2개의 주문을 열어 1개를 취소했다. 상세에는 취소 1개·남음 1개·취소 금액 19,000원이 표시됐다. 남은 1개를 전체 취소한 뒤 취소 금액은 38,000원, 남은 금액은 0원이 됐다. API 상태에서 재고가 주문 전 3개로 복구된 것도 확인했다.
- 같은 주문에서 `다시 담기`를 눌렀을 때 최초 주문 수량 2개가 장바구니에 표시됐고 주문 기록 3건은 유지됐다. 재고는 다시 담기만으로 차감되지 않았다.
- 서버를 같은 임시 DB로 재시작한 뒤 주문, 취소 금액, 장바구니 자료가 유지됨을 확인했다. 다른 고객의 주문 목록에는 고객 1의 주문이 표시되지 않았다.
