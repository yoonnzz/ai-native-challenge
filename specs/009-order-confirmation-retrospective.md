# SPEC 009: 주문 확인 내용과 확정 주문 일치 (사후 기록)

## 기록 시점과 누락

- 관련 요구사항: 17 주문 확인, 18 주문 확정.
- 변경은 2026-09-29 커밋 `0056d05`와 PR #2에서 먼저 구현·병합됐다. 구현 착수 전에 새 SPEC을 작성하지 못했다. 이 문서는 그 누락을 숨기지 않고 변경 내용과 근거를 사후에 보완한다.
- 이 수정에 대해 사용자가 별도로 정한 처리 기준이나 이유는 기록에서 확인되지 않았다. 아래 이유는 요구사항 17~18과 코드·테스트를 대조한 AI의 설명이며, 사용자 판단으로 표시하지 않는다.

## 변경 기준과 이유

- 기존 화면은 확인 뒤 선택 상품이 같은 금액의 다른 옵션으로 바뀌거나 배송지가 수정되어도 확인 화면이 남을 수 있었다. 그러면 고객이 확인한 내용과 실제 확정 내용이 달라질 수 있다.
- 서버는 `/api/quote`의 선택 상품·수량·배송 정보·메모·할인·배송비·최종 금액에 연결된 `confirmationKey`를 반환한다. `order.place`는 현재 주문 내용을 다시 계산해 키가 일치할 때만 확정한다. 일치하지 않으면 다시 확인하라는 오류를 반환한다.
- 화면은 주문 입력이 바뀌면 이전 확인 내용을 감추고, 확정 요청에 직전 확인 키를 전달한다. 이 기준은 확정 전 확인한 상품과 배송 정보가 실제 주문과 일치하도록 하기 위한 것이다.
- API 변경은 `docs/API.md`에 반영됐다. 이후 생성기가 확인 키를 전달하도록 한 수정과 검증은 [SPEC 008](008-generated-orders-confirmation.md)에 별도로 기록돼 있다.

## 구현·확인 결과

- 구현 근거: `server/core.ts`, `src/main.tsx`, `docs/API.md`, `tests/shop.test.ts`의 커밋 `0056d05`.
- 추가된 자동 테스트는 같은 금액의 선택 옵션 교체와 배송지 수정 뒤 옛 키로 주문을 거절하고, 새 확인 키로는 주문을 확정하는 경우를 검사한다.
- 2026-09-29 최신 `main`에서 AI가 `npm test`를 실행해 12건 통과했고 `npm run build`도 성공했다. 이 결과에는 뒤이은 생성기 수정의 테스트가 포함된다.
- 이 SPEC을 위한 별도 브라우저 화면 조작과 사용자의 직접 확인은 수행하지 않았다. 자동 테스트·빌드 통과와 사람의 확인을 구분한다.
