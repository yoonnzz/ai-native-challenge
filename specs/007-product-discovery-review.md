# SPEC 007: 상품 탐색 요구사항 1~6 검증 기록

## 범위와 판단

- 2026-09-29 사용자 요청: 상품을 찾고 고르는 요구사항 1~6이 구현되어 있는지 단계적으로 확인한다.
- 이번 작업은 기존 구현의 검토와 기록이다. 상품 표시 방식이나 기능 코드는 변경하지 않는다.
- 사용자 결정: `품절`은 재고 0개라는 뜻이므로 `재고 0개`를 별도로 표시할 필요가 없다. 현재 품절 표시는 유지한다. 이 결정은 AI의 제안이나 화면 검사 결과가 아니다.

## AI가 실행한 확인

기존 자료를 보존하기 위해 별도 임시 SQLite DB로 앱을 실행했다. 제공된 `initial-data.json`과 임시 DB의 SKU별 가격·재고를 비교한 결과, 30개 옵션 모두 일치했다. 고객은 1 김가온, 2 이누리, 3 박다온, 4 최라온으로 일치했다. `npm test`는 9개 모두 통과했고 `npm run build`도 성공했다.

| 번호 | 요구사항 | AI 확인 결과 | 근거와 범위 |
|---|---|---|---|
| 1 | 고객 전환 | 구현 확인 | 화면에서 4명 선택과 고객 1·2의 찜 분리를 확인했다. 별도 인메모리 실행에서 고객 1의 장바구니·찜·배송지·쿠폰 사용·주문과 고객 2~4의 빈 자료가 분리되어 반환됐다. 모든 자료를 고객 전환 화면에서 각각 직접 조작한 검사는 아니다. |
| 2 | 상품 목록 | 구현 확인 | 화면에 옵션 30개와 SKU·상품명·옵션·가격·재고 또는 품절이 표시됐다. 초기 SKU별 가격·재고는 제공 자료와 일치했다. 품절 옵션의 담기 버튼은 비활성화됐다. |
| 3 | 상품 검색 | 구현 확인 | 옵션명 `크림` 검색에서 품절 옵션 2개, 상품명 `데일리 티셔츠` 검색에서 3개가 표시됐다. 검색어를 지우자 전체 목록으로 돌아왔다. |
| 4 | 상품 필터 | 구현 확인 | 전체 30개, 구매 가능 26개, 품절 4개를 확인했다. `크림` 검색과 구매 가능 필터를 함께 적용하면 결과 0개였다. |
| 5 | 상품 정렬 | 구현 확인 | 화면에서 가격 높은 순과 낮은 순의 결과 순서를 확인했다. `검정` 검색과 구매 가능 필터를 함께 적용한 8개 결과에 가격 높은 순이 적용됐다. 상품명 순 선택과 이름 기준 정렬 코드를 확인했다. |
| 6 | 찜 목록 | 부분 확인 | 화면에서 고객 1이 SKU 1을 찜하자 찜 목록에 1개가 표시됐고 고객 2의 목록은 0개였다. 찜 후 SKU 1 재고는 3개로 유지됐다. 찜 해제 처리 코드는 확인했으나 화면에서 해제 후 목록이 비는 결과는 확인하지 못했다. |

## 사람의 확인과 남은 작업

- 사용자가 직접 화면을 조작해 확인한 결과는 아직 전달받지 않았다.
- 사용자 확인 사례 제안: 고객 1의 찜 목록에서 SKU 1의 하트를 눌러 목록이 0개가 되고 재고는 3개로 유지되는지 확인한다. 실제 결과를 받기 전에는 완료로 기록하지 않는다.
- 이번 검토에서 확정된 기능 오류는 없다. 찜 해제 화면 결과는 미확인이다.
