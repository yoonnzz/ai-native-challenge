## 기존 과제 기준 유지

- 제공 초기 데이터로 먼저 구현·검증한 뒤 별도 테스트 환경에서 대량 데이터를 생성·검증한다.
- 실행 명령, 초기·테스트 환경 선택 및 재생성·검증 방법은 실제 구현 후 SUBMISSION.md에 기록한다.
- API 문서는 실제 구현과 일치하게 docs/에 작성한다.
- PDF는 선택 가능한 텍스트를 포함한다. 제출물에 앱·데이터 생성 코드·전체 SPEC·API 문서·PDF·SUBMISSION.md를 포함한다.
- 기존 자료는 보존하고 비밀번호·API 키·개인정보·불필요한 설치 폴더는 제출에서 제외한다.

## 후속 구현·확인 기록 (2026-09-29, 사후 정리)

위 상태는 최초 계획을 작성한 시점의 기록이다. 이후 React·TypeScript 화면, Node.js·TypeScript API, 로컬 SQLite 저장소와 API 문서 `docs/API.md`를 구현했다. 초기 데이터와 별도 SQLite 파일에 상품 옵션 200개·고객 100명·주문 800개를 생성했고, 재고·취소 금액 및 기존 파일 보존 확인 결과는 [SPEC 008](008-generated-orders-confirmation.md)에 기록돼 있다. 기존 SPEC 006·007 두 파일에는 브라우저와 API 확인 범위가 남아 있다. SPEC 008에 기록된 최종 자동 테스트 결과는 12건 통과다. 이 문서 보완에서 테스트·브라우저 검사를 새로 실행하지 않았다.

`과제설명.pdf` 파일은 현재 저장소에 있으나, 제출 PDF 내용·제출 ZIP 완성 여부 및 사용자 직접 조작 확인은 이 기록만으로 완료로 판정하지 않는다. 사용자는 화면 확인을 우선하고 PDF·제출 문서 작업을 잠시 보류하도록 요청했다.
